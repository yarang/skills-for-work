# 보안 리뷰

`code-principles`의 불변 규칙(비밀, 경계 검증, 에러 삼키기 금지, 매개변수화)을 **공격자 입장에서** 확인하는 점검표입니다. 바뀐 코드에서 출발해, 신뢰하지 않는 입력이 어디까지 흘러가는지 따라갑니다.

## 절차

1. 바뀐 파일 목록을 받고(`git diff --name-only <기준>...HEAD`), **신뢰 경계**를 찾습니다: HTTP 핸들러, MCP 도구, Tauri 명령, CLI 인자, 파일·환경변수 읽기, 외부 API 응답.
2. 각 경계에서 입력이 어디에 쓰이는지(쿼리, 셸, 경로, HTML, URL, 역직렬화) 따라갑니다.
3. 아래 점검표를 해당하는 항목만 확인합니다.
4. 의존성 매니페스트가 바뀌었으면 「의존성」 절의 명령을 실행합니다.
5. 「출력 형식」으로 보고합니다. 근거 없는 추측은 적지 않고, 확인하지 못한 것은 「확인 못 함」에 적습니다.

## 점검표

### 비밀
- [ ] 코드, 테스트, 설정 예시, 커밋된 `.env`에 실제 키·토큰·비밀번호가 없음
- [ ] 비밀이 로그, 에러 메시지, 응답 본문, 도구 결과, URL 쿼리에 들어가지 않음
- [ ] 프론트엔드 번들에 들어가는 환경변수(`VITE_*`, `NEXT_PUBLIC_*`)에 비밀이 없음

### 주입
- [ ] SQL은 매개변수 바인딩만 씀. 문자열 연결·포맷으로 만든 쿼리 없음(ORM의 raw 쿼리 포함)
- [ ] 셸 명령은 인자 배열로 실행함. `shell=True`, `sh -c "<입력>"`, 템플릿 문자열 명령 없음
- [ ] 파일 경로 입력은 기준 디렉터리로 정규화한 뒤 그 안에 있는지 확인함(`..`, 심볼릭 링크, 절대 경로)
- [ ] 정규식에 사용자 입력을 넣을 때 이스케이프함. 역추적 폭발(ReDoS) 위험 패턴 없음

### 인증·인가
- [ ] 새 엔드포인트·명령·도구에 인증이 걸려 있음. 기본값이 "열림"이 아님
- [ ] 객체 단위 인가: ID로 조회한 자원이 요청자 것인지 확인함(IDOR)
- [ ] 비밀번호는 argon2·bcrypt·scrypt로 해시함. 토큰 비교는 상수 시간 비교를 씀
- [ ] 세션·토큰에 만료가 있고, 쿠키는 `HttpOnly`, `Secure`, `SameSite`가 설정됨

### 웹
- [ ] 정화되지 않은 HTML 삽입(`dangerouslySetInnerHTML`, `innerHTML`, `v-html`) 없음
- [ ] 사용자 입력으로 만든 링크에서 `javascript:` 스킴을 막음
- [ ] 쿠키 인증을 쓰는 상태 변경 요청에 CSRF 방어가 있음
- [ ] CORS가 인증과 함께 와일드카드 출처를 허용하지 않음

### 외부 호출
- [ ] 사용자가 준 URL로 서버가 요청하면(SSRF) 허용 목록 또는 사설 IP 대역 차단이 있음
- [ ] 외부 응답을 검증 없이 신뢰하지 않음(크기 상한, 스키마 검증)
- [ ] TLS 검증을 끄지 않음(`verify=False`, `rejectUnauthorized: false`, `danger_accept_invalid_certs`)

### 역직렬화와 자원
- [ ] 신뢰하지 않는 데이터에 `pickle`, `yaml.load`(SafeLoader 없이), `eval`, `new Function` 없음
- [ ] 요청 본문·업로드 크기, 페이지 크기, 반복 횟수에 상한이 있음

### 암호화
- [ ] 직접 만든 암호 알고리즘이 없음. 난수는 암호학적 생성기(`secrets`, `crypto.randomUUID`, `rand::rngs::OsRng`)를 씀
- [ ] MD5·SHA-1을 보안 목적으로 쓰지 않음

### MCP 서버
- [ ] 도구 인자로 비밀을 받지 않음. 도구 결과에 비밀이 없음
- [ ] 파일·셸·네트워크 도구의 범위가 좁고, 쓰기 도구는 읽기 도구와 분리됨
- [ ] 외부 데이터(웹 페이지, 이슈 본문)를 도구 결과로 돌려줄 때, 그 안의 지시문이 모델을 조종할 수 있다는 점(프롬프트 주입)을 설계에서 고려함
- [ ] HTTP 전송이면 `Origin` 검증과 바인딩 주소 제한이 있음

### Tauri
- [ ] capability 권한이 최소이고 범위가 지정됨. CSP가 꺼져 있지 않음
- [ ] 명령 인자를 웹뷰에서 온 신뢰하지 않는 입력으로 검증함
- [ ] 원격 URL을 웹뷰에 로드하지 않음

## 의존성

매니페스트나 잠금 파일이 바뀌었을 때 실행합니다. 도구가 없으면 「확인 못 함」에 적습니다.

| 언어 | 명령 |
|---|---|
| TypeScript | `npm audit --omit=dev` / `pnpm audit --prod` |
| Python | `uv run pip-audit` 또는 `pip-audit` |
| Go | `govulncheck ./...` |
| Rust | `cargo audit` |

- 새 의존성은 이름이 유명 패키지와 비슷한 가짜(타이포스쿼팅)가 아닌지, 관리가 이어지고 있는지 확인합니다.
- 잠금 파일 없이 의존성이 추가되지 않았는지 확인합니다.

## 심각도

| 심각도 | 기준 | 예 |
|---|---|---|
| **CRITICAL** | 원격에서 인증 없이 악용 가능, 또는 비밀·개인정보가 이미 노출됨 | SQL 주입, 커밋된 실제 키, 인증 없는 관리자 엔드포인트 |
| **HIGH** | 조건이 있지만 악용 가능, 또는 방어 계층 하나가 빠짐 | IDOR, 경로 탐색, SSRF, 정화 없는 HTML |
| **MEDIUM** | 다른 취약점과 엮이면 위험, 또는 모범 사례 위반 | 쿠키 속성 누락, 크기 상한 없음, 넓은 Tauri 권한 |
| **LOW** | 위생 문제 | 오래된 의존성(알려진 취약점 없음), 과한 에러 상세 |

## 출력 형식

```
## 보안 리뷰 결과
- 범위: <확인한 파일·경계>
- 판정: 차단 | 경고 | 통과   (CRITICAL 있으면 차단, HIGH만 있으면 경고)

### 발견
1. [CRITICAL] <파일:줄> — <한 줄 요약>
   - 공격 시나리오: <입력 → 흐름 → 피해>
   - 고칠 방법: <구체적으로>

### 확인 못 함
- <무엇을, 왜>
```
