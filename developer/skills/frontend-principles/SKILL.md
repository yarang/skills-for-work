# 프론트엔드 원칙

프론트엔드 코드는 **사용자 기기에서 실행되고, 사용자가 전부 볼 수 있습니다.** 이 사실이 백엔드와 정반대인 규칙들을 만듭니다.

## 설정과 비밀값

- **빌드 시점 환경변수는 공개됩니다.** `VITE_*`, `NEXT_PUBLIC_*`, `import.meta.env`로 읽는 값은 번들에 그대로 들어갑니다.
- 그래서 비밀값(API 키, 토큰, DB 접속 정보)은 **프론트엔드에 절대 두지 않습니다.** 비밀값이 필요한 호출은 백엔드나 프록시 뒤로 보냅니다.
- 공개해도 되는 값(공개 API 주소, 기능 플래그)만 빌드 설정으로 받습니다. 설정은 한 모듈에서 읽어 타입을 붙여 내보내고, 곳곳에서 `import.meta.env`를 직접 읽지 않습니다.
- 인증 토큰은 가능하면 HttpOnly 쿠키에 둡니다. `localStorage`에 두면 XSS 한 번으로 탈취됩니다.

## 상태

- **서버 상태와 UI 상태를 분리합니다.**
  - 서버 상태는 원본이 서버에 있는 데이터입니다. 쿼리 캐시 라이브러리로 다루고, 전역 스토어에 복사하지 않습니다.
  - UI 상태는 열림/닫힘, 입력 중인 값, 선택 항목입니다. 쓰는 컴포넌트 가까이에 둡니다.
- 다른 상태에서 계산할 수 있는 값은 상태로 두지 않고 계산합니다.
- 공유할 이유가 생길 때만 상태를 위로 올립니다. 처음부터 전역에 두지 않습니다.
- URL로 표현할 수 있는 상태(필터, 페이지, 탭)는 URL에 둡니다. 새로고침과 공유가 됩니다.

## 경계

- 서버 응답도 외부 입력입니다. 응답 스키마를 런타임에 검증(zod 등)하거나, 생성된 타입을 씁니다.
- 프론트엔드 검증은 **사용성**을 위한 것입니다. 보안 검증은 항상 백엔드가 다시 합니다.
- API 호출은 도메인별 모듈 한 곳에 둡니다. 컴포넌트 안에서 `fetch`를 직접 부르지 않습니다.

## 화면 상태

- 데이터를 보여주는 모든 화면은 **로딩 / 에러 / 빈 결과 / 정상** 네 상태를 다룹니다.
- 에러 화면에는 사용자가 할 수 있는 다음 행동(다시 시도, 돌아가기)을 둡니다. 스택 트레이스나 내부 메시지를 보여주지 않습니다.
- 사용자 입력을 받는 동작은 중복 제출을 막습니다.

## 접근성

- 클릭 가능한 것은 `button`이나 `a`로 만듭니다. `div`에 `onClick`을 붙이지 않습니다.
- 폼 입력에는 연결된 `label`을 둡니다. 이미지에는 `alt`를 둡니다(장식이면 빈 값).
- 키보드만으로 모든 기능을 쓸 수 있어야 하고, 포커스가 보여야 합니다.
- 색만으로 정보를 전달하지 않습니다. 대비는 WCAG AA(본문 4.5:1)를 지킵니다.

## 보안

- 사용자나 서버에서 온 HTML을 그대로 렌더링하지 않습니다. 꼭 필요하면 검증된 sanitizer를 거칩니다.
- `eval`, `new Function`, 문자열 `setTimeout`을 쓰지 않습니다.
- 외부 링크(`target="_blank"`)에는 `rel="noopener noreferrer"`를 둡니다.

## 성능

- 라우트 단위로 코드를 나눠 불러옵니다.
- 큰 라이브러리를 들이기 전에 번들 크기를 확인합니다.
- 긴 목록은 가상화하고, 이미지는 크기를 지정하고 지연 로드합니다.
