# 저장소 문서 갱신

코드 변경이 문서에 반영되지 않으면 문서는 거짓말을 합니다. 이 스킬은 **무엇을 언제 고칠지**의 기준입니다. 문서의 문체나 구조를 다시 쓰는 일이 아니라, 코드와 어긋난 부분만 바로잡습니다.

## 어떤 문서를 언제 고치는가

| 문서 | 고치는 때 |
|---|---|
| `README.md` (저장소 루트) | 설치·사용·명령·설정이 바뀔 때 |
| `MANUAL.md` | 사용자 절차가 바뀔 때 |
| `CHANGELOG.md` | 사용자에게 보이는 변경마다. Keep a Changelog 형식의 `Unreleased` 절에 적습니다 |
| 하위 디렉터리 `README.md` | 그 디렉터리의 구조·사용법이 바뀔 때 |

- 바뀐 것이 사용자에게 보이지 않으면(내부 리팩터링, 테스트 정리) README·MANUAL은 고치지 않습니다. CHANGELOG는 사용자에게 보이는 변경에만 씁니다.
- 없는 문서를 새로 만들지 않습니다. 문서가 없는 저장소에서 문서 체계를 새로 세우는 일은 사용자의 결정이므로, 필요하다고 판단되면 「물어볼 것」에 적습니다.

## ADR (Architecture Decision Record)

**쓸 때** — 다음 조건에 해당하는 결정이 이번 변경에 들어 있을 때:

- 되돌리기 어려운 결정 (데이터 모델, 공개 인터페이스, 외부 의존성 도입)
- 대안을 버린 결정 (왜 그 대안이 아닌지가 나중에도 궁금해질 때)
- 여러 모듈에 걸친 결정

**형식** — `docs/adr/NNNN-<제목>.md`. 순서는 상태 → 맥락 → 결정 → 결과입니다. 번호 `NNNN`은 기존 ADR의 최대 번호 + 1입니다 (기존 것이 없으면 `0001`).

**대체** — 기존 ADR의 결정을 뒤집을 때는 기존 파일을 고치지 않고 새 ADR을 씁니다. 기존 ADR의 상태 줄만 바꿉니다: `상태: 대체됨 — NNNN` (새 ADR 번호). 어떤 맥락에서 그 결정이 내려졌는지는 역사 기록으로 남겨야, 나중에 같은 논의를 다시 하지 않습니다.

## 코드와 문서가 어긋났는지 찾는 법

1. `git diff --no-ext-diff --no-textconv <작업 시작 커밋>` 에서 바뀐 **공개 함수·명령·설정 키·환경 변수**를 뽑아냅니다.
2. 뽑아낸 이름마다 문서에서 `grep` 으로 검색합니다. 문서에 있는데 코드에서 사라졌거나, 코드에 새로 생겼는데 문서에 없으면 그곳을 고칩니다.
3. 이름이 같고 동작이 바뀐 경우(기본값 변경, 반환 형식 변경)는 diff의 내용에서 찾습니다. 문서의 서술이 새 동작과 어긋나면 고칩니다.

## 쓰지 않는 것

- 코드 주석 안의 문서 — 코드에 직접 다는 주석은 코드 변경이 고칩니다.
- 설계서 (`docs/designs/`) — 승인된 설계서는 고칠 수 없습니다. 설계가 바뀌어야 한다고 판단되면 「물어볼 것」에 적습니다.
- 자동 생성 문서 — 도구가 만드는 파일(API 참조, 잠금 파일 요약)은 손으로 고치지 않습니다. 다시 생성하는 명령이 필요하면 「물어볼 것」에 적습니다.
