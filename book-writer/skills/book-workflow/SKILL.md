# 교재 집필 절차

장 하나는 아래 여섯 단계를 순서대로 지납니다. **스토리와 내용은 사람과 논의해 승인받기 전에는 다음 단계로 넘어가지 않습니다.**
글을 먼저 쓰고 나중에 방향을 고치면 다시 쓰는 비용이 가장 크기 때문입니다.
book-principles는 '무엇을 지킬지', korean-style은 '어떻게 표기할지', 이 스킬은 '어떤 순서로 쓸지'를 적습니다.
책마다 다른 것(권·Part 구성, 도구, 분량)은 그 책의 집필 규칙 문서(CLAUDE.md가 가리키는 `WRITING.md`)와 `DECISIONS.md`가 정합니다.

## 0. 단계와 관문

| 단계 | 하는 일 | 산출물 | 맡는 쪽 | 관문 |
|---|---|---|---|---|
| ① 스토리 | 이 장이 독자에게 들려줄 이야기를 정합니다 | `plans/vol<N>/ch<NN>/story.md` | planner가 안 2~3개 제안 → 메인 세션이 사람과 논의 | **사람 승인** |
| ② 내용 | 개념·실습·결과물·필요한 사실을 정합니다 | `plans/vol<N>/ch<NN>/content.md` | planner 초안 + researcher(사실) + capturer `probe`(실측 가능 여부) → 사람과 논의 | **사람 승인** |
| ③ 구조 | 장 템플릿에 맞춰 절별 개요, 그림·표·코드 목록, 분량을 짭니다 | `plans/vol<N>/ch<NN>/outline.md` | planner | **사람 확인** — 메인 세션이 개요를 보여 주고 사람이 확인하면 메인 세션이 `승인`을 기록합니다. 답이 없으면 통과가 아닙니다 |
| ④ 집필 | 개요대로 원고를 씁니다 | `manuscript/…/chNN.md` | writer(`draft`) | **변경 범위 검증** 통과(바꾼 파일만, 아래 「검증의 두 단계」) |
| ⑤ 검토 | 초안을 독립적으로 검토하고 고칩니다 | `reviews/editor-vol<N>-ch<NN>-<날짜>-r<회차>.md` | editor + 외부 검토(Codex·Antigravity) → writer(`revise`) | blocker 0, major는 반영 또는 사유 |
| ⑥ 완료 | 실측·캡처를 채우고 상태를 닫습니다 | manifest `완료`, 실측 기록 | capturer(`shoot`) → writer → editor(변경분 재검토), 메인 세션 | **완료 검증** 통과 + **사람 승인** |

- 각 산출물 맨 위에 `상태: 제안 | 논의 중 | 승인 (<날짜>)`과 '결정 사항' 목록을 둡니다. 승인된 문서를 바꾸려면 사람과 다시 논의합니다.
- 사람과 논의하는 것은 **메인 세션**입니다. 하위 에이전트는 사람에게 직접 묻지 못하므로, 안과 '물어볼 것'을 만들어 넘깁니다.
- **승인된 계획을 다시 논의할 때**: planner가 `<문서>.rev<N>.md`에 `상태: 제안`으로 수정안을 씁니다(예: `story.rev1.md`). 사람이 수정안을 승인하면 메인 세션이 원본을 교체하고, 아래 단계 문서(content·outline)를 `재확인 필요`로 바꿉니다.
- **이미 원고가 있는 장**: planner가 `extract` 모드로 현재 원고에서 story·content·outline을 '현행안'으로 뽑습니다(상태: 제안, 안 A = 현행). 사람이 현행안을 승인하면 바로 ⑤ 검토로 가고, 바꾸기로 하면 ①부터 다시 논의합니다. 다시 쓰는 안에는 버리게 되는 실측·결과물·뒤 장 의존을 비용으로 적습니다.
- 작은 수정(오탈자, 표기, 검토 지적 반영)은 ④⑤만 돕니다. 장의 흐름이나 실습이 바뀌는 수정은 ①이나 ②로 돌아갑니다.
- manifest의 상태값은 `미착수 / 스토리 / 내용 / 구조 / 초안 / 검토 / 완료`를 씁니다. **상태값 목록은 이 스킬에만 둡니다** 다른 스킬·책 문서는 이 목록을 가리킵니다. 상태는 관문마다 **메인 세션이** 바꾸고, writer는 `초안`만 씁니다.

## 검증의 두 단계

- **변경 범위 검증** — writer가 작업마다, **이번에 바꾼 파일만**.
  - 표기 검사: 이번에 고친 파일의 고칠 곳이 0, 전체 저장소의 고칠 곳이 기준선보다 늘지 않음.
  - 빌드: 저장소에 빌드가 있으면 이번에 고친 권만.
  - 예제 꾸러미: 매핑된 코드 블록을 고쳤을 때만 다시 만들고 테스트.
- **완료 검증** — ⑥에서 메인 세션이 장 전체를 한 번.
  - 표기 검사 0, 조판 빌드 성공, 예제 꾸러미 테스트 통과, 검토 blocker 0, 실측 필요 표시 0.

## ① 스토리 논의
목표: 독자가 이 장을 읽고 '무엇이 달라지는가'를 한 문장으로 말할 수 있게 합니다.
- 정할 것: 독자의 출발점(앞 장에서 무엇을 가졌나), 이 장의 문제 상황, 전환점(깨닫는 순간), 끝에 손에 쥐는 결과물, 중심 비유, 다음 장으로 넘기는 것.
- planner는 서로 다른 안 2~3개를 냅니다(예: 실패에서 시작 / 결과물에서 거꾸로 / 비교로 시작). 안마다 장단점과 앞뒤 장과의 연결을 적습니다.
- 메인 세션은 안을 사람에게 보여 주고, 고른 안과 고친 점을 `story.md`의 '결정 사항'에 적은 뒤 승인 표시를 합니다.
- 틀: `templates/story.md`

## ② 내용 논의
목표: 무엇을 가르치고 무엇을 따라 하게 할지 확정합니다. 아직 문장은 쓰지 않습니다.
- 정할 것: 학습 목표 3~5개, 개념 목록(처음 나오는 용어와 비유), 따라하기 시나리오(입력·기대 결과), 혼자하기·도전하기 과제, 실습 결과물 번호, 다루지 않는 것.
- 사실 확인이 필요한 항목은 researcher에게, 화면·동작이 실제로 되는지는 capturer에게 **`probe` 모드**(원고 없이 동작 목록만으로 실측 기록을 남기는 모드)로 미리 보냅니다. 결과는 '근거' 칸에 링크합니다.
- 실측할 수 없는 실습은 이 단계에서 바꿉니다(④에서 발견하면 늦습니다).
- 틀: `templates/content.md`

## ③ 구조화
- 승인된 스토리·내용을 장 템플릿(「장 템플릿」 절)에 배치합니다. 절마다 한 줄 목적, 들어갈 개념·실습, 그림·표·코드(번호, 종류, 캡션 초안, 실측 필요 여부), 목표 쪽수를 적습니다.
- 분량 합계가 책의 목표 범위 안인지, 앞뒤 장의 결과물 번호와 맞는지 확인합니다.
- 메인 세션이 완성된 개요를 사람에게 보여 주고, 확인 답을 받으면 `outline.md`에 승인 표시를 합니다. 답을 받지 못했으면 승인이 아닙니다.
- 틀: `templates/outline.md`

## ④ 집필
- writer가 `draft` 모드로 `outline.md`를 따라 씁니다. 개요에서 벗어나야 하면 쓰지 말고 보고서의 '제안'으로 올립니다.
- 실측 전 화면·출력은 `<!-- 실측 필요: … -->`로 남깁니다. 지어내지 않습니다.
- 끝나면 **변경 범위 검증**(이번에 쓴 파일만: 표기 검사 0, 고친 권 빌드, 매핑된 코드 블록을 고쳤으면 꾸러미 테스트)을 돌립니다. 장 전체의 완료 검증은 ⑥에서 합니다. manifest의 상태를 `초안`으로 바꿉니다.

## ⑤ 초안 검토
- editor가 story·content·outline과 초안을 대조해 검토합니다(흐름, 목표 달성, 실습 재현성, 초보자 눈높이, 표기). 결과는 `templates/review.md` 형식으로 `reviews/editor-vol<N>-ch<NN>-<날짜>-r<회차>.md`에 남깁니다. 회차는 그 장·그 날짜의 기존 기록 다음 번호로 정해 같은 날 재검토가 덮어쓰지 않게 합니다.
- 사용자 지침에 외부 검토가 있으면 같은 기준으로 Codex·Antigravity에도 맡깁니다. 기준 파일(이 스킬, book-principles, korean-style, 책의 집필 규칙)과 계획 문서를 함께 넘깁니다.
  - `codex exec "<기준 파일 내용> … plans/vol1/ch02/와 manuscript/vol1/part1/ch02.md를 검토하라. 지적마다 파일:줄, 근거, 독자가 겪을 문제, 심각도"`
  - `agy -p "<같은 지시>"`
- writer가 `revise` 모드로 반영합니다. 반영하지 않은 지적은 이유를 남깁니다.
- 검토는 최대 2회 돕니다. 2회 뒤에도 blocker가 남으면 사람에게 올립니다.

## ⑥ 완료
- capturer가 `shoot` 모드로 '실측 필요'를 채우고 캡처를 정리합니다. writer가 결과를 반영합니다.
- **실측 반영 뒤 재검토**: 이 단계에서 명령, 출력, 실습 단계가 바뀌면 editor가 **그 변경분만** 다시 검토한 뒤 완료합니다. 변경이 없으면 재검토 없이 진행합니다.
- 메인 세션이 **완료 검증**(장 전체: 표기 검사 0, 빌드 성공, 예제 꾸러미 테스트, `실측 필요` 표시 0, 검토 blocker 0)을 돌립니다. ⑥에서 `git status`로 이 장 범위 밖의 변경이 없음을 확인합니다.
- 완료 체크리스트(「완료 체크리스트」 절)를 모두 통과하면 메인 세션이 사람에게 요약(바뀐 점, 남은 위험, 쪽수)을 보여 주고 승인받습니다. 승인 뒤 manifest를 `완료`로 바꾸고 커밋합니다.

## 앞붙이

머리말, 이 책을 읽는 방법, Part 도입도 같은 단계로 지나되, 장과 다른 규칙을 씁니다.

- 식별자는 `front/<이름>`(예: `front/preface`, `front/how-to-read`, `front/part1-intro`). 원고는 `manuscript/<권>/front/<이름>.md`, Part 도입은 `manuscript/<권>/part<N>/intro.md`에 둡니다.
- 계획 문서는 `plans/front/<이름>/`에 `story.md`(의도)와 `outline.md`만 씁니다. `content.md`는 쓰지 않습니다.
- 내용 종류: Part 도입(반 쪽, 만드는 것과 이어받는 것), 머리말(의도만), 이 책을 읽는 방법(장 구성, 상자, 표기, 준비물, 장마다 만든 것과 다시 쓰는 곳, 예제 받는 법).
- 완료 체크리스트는 「완료 체크리스트」의 앞붙이 변형(실습 항목 제외)을 씁니다.

## 장 템플릿

```markdown
# N. 제목

## 🎯 이 장에서 배우는 것
- 3~5개, '~할 수 있습니다'로 끝냅니다

## 💡 개념 설명
- 일상 비유로 시작 → 핵심 개념 1~2문단 → 코드·그림 예시
- '왜 중요한가' 1문단(실무와의 연결)

## 📝 따라하기
- 단계마다: 할 일 → 입력(요청문·명령) → 보이면 성공인 결과

## ✏️ 혼자하기
- 따라하기를 조금 바꾼 과제. 과제 문단 바로 아래 번호 목록으로 요령 2~3개('힌트' 제목 줄은 달지 않습니다)

## 🚀 도전하기
- 방향만 주고 세부는 열어 둡니다

## ⚠️ 주의사항 / 자주 하는 실수

## ✅ 자가진단 체크리스트

## 📌 핵심 요약
- 3줄 이내
```

- 독자용 어조: 초보자~중급자에게 격려하는 말('해 보세요!')을 쓰고, 실패를 배울 기회로 다시 설명하며, 전문 용어는 처음 나올 때 비유와 함께 들입니다. 계획 문서·보고서는 짧고 직접적으로 씁니다.
- 실습 결과물 번호는 Part별 `P<n>-①`부터. 앞 Part의 결과물은 정의된 Part 번호로 가리킵니다.
- 복합 실습 장: 선택 장은 건너뛰어도 되게 쓰고 뒤 장에 '건너뛰었다면' 우회 안내를 둡니다. 필수 장은 '선택 심화' 표시를 쓰지 않습니다. 어느 장이 어느 쪽인지는 책의 집필 규칙이 정합니다.
- 권이 여러 권일 때 권 사이를 어떻게 가리킬지는 책의 집필 규칙 문서가 정합니다.

## 완료 체크리스트

장:
- [ ] story·content·outline이 모두 `승인` 상태이고, 원고가 그와 어긋나지 않습니다
- [ ] 따라하기·혼자하기·도전하기를 모두 담았습니다
- [ ] 화면·출력이 모두 실측한 것입니다(`실측 필요` 표시 0)
- [ ] 그림·표·코드 캡션과 번호 참조, 실습 결과물 번호가 맞습니다
- [ ] 완료 검증을 통과했습니다(표기 검사 0, 빌드 성공, 예제 꾸러미 테스트)
- [ ] 검토 blocker 0, 반영하지 않은 지적은 이유가 남아 있습니다. 실측 반영으로 바뀐 부분은 재검토를 지났습니다
- [ ] 목표 분량 안입니다
- [ ] manifest가 갱신되었습니다
