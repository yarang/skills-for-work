# 한국어 기술서 표기

국립국어원 한글 맞춤법과 문장 부호 규정을 기본으로 한다. 책의 집필 규칙 문서에 예외가 있으면 그쪽을 따른다.
표기 규칙을 근거로는 코드 블록 안이나 따옴표 안에 옮긴 실제 입력 문구를 고치지 않는다. 기술 오류(틀린 명령, 틀린 설정값)의 수정은 writer의 `revise` 범위다 — 표기 규칙과 무관하게 고친다.

## 1. 어미
- 본문은 합니다체('~입니다', '~합니다')로 쓴다. 해요체('~예요', '~해요')는 쓰지 않는다.
- 권유('~해 보세요')와 청유('~해 봅시다'), 질문('~일까요?')은 쓸 수 있다.
- 한 블록(문단, 상자, 목록 하나) 안에서는 평서·권유·청유 중 주된 형태를 하나로 맞춘다. 같은 목록의 항목끼리는 형태를 맞춘다.
- 목표·체크리스트·요약처럼 독자의 상태를 적는 목록은 평서('~할 수 있습니다')로 끝낸다.
- 명사로 끝나는 목록 항목, 표 칸, 캡션은 어미를 붙이지 않는다.

## 2. 따옴표와 인라인 코드
| 표기 | 쓰는 곳 |
|---|---|
| 큰따옴표 "" | 직접 한 말, 그대로 옮긴 인용, AI에게 실제로 입력하는 요청문, 결과물에 글자 그대로 적히는 고정 문구, 화면에 뜨는 문구 |
| 작은따옴표 '' | 강조, 개념에 붙인 이름, 마음속 말, 인용 안의 인용, 메뉴·버튼·항목 이름, 파일·폴더 이름 |
| 인라인 코드 | 독자가 글자 그대로 입력하거나 설정 파일에 적는 것: 명령, 설정 키·값, 도구·Skill·에이전트 이름, 권한 규칙, 마크다운 문법 |

- 한국어 문장·문구는 인라인 코드로 쓰지 않는다(큰따옴표).
- 인라인 코드는 판에서 글꼴로만 구별될 수 있으니 구별이 꼭 필요한 것에만 쓴다.
- 작은따옴표로 쓴 파일 이름의 `~`, `_`, `<`, `*`는 마크다운에서 `\~`, `\_`, `\<`, `\*`로 이스케이프한다.

## 3. 띄어쓰기
- 보조용언 '-어 보다 / -어 주다 / -어 두다'는 띄어 쓴다(해 보세요, 적어 두세요, 보여 줍니다).
- 한 단어로 굳은 말은 붙인다: 물어보다, 알아보다, 찾아보다, 돌아보다, 훑어보다, 살펴보다, 지켜보다, 눈여겨보다, 돌려주다, 도와주다, 넘겨주다, 내주다.
- 의존명사는 띄운다: 할 수 있다, 하는 것, 할 때, 해야 한다, 한 번.
- 한 단어로 쓰는 말: 그다음, 그중, 그때, 함께하다, 더하다, 빈칸, 내려받다, 워크플로, 체크리스트.
- 숫자·영문과 한글 사이에 자동 간격을 넣지 않는다. 조사는 앞말의 발음에 맞춘다('4-4로', 'Skill을', 'MCP를').

## 4. 용어
- 전문 용어는 처음 나올 때 비유나 풀이와 함께 도입하고, 그 뒤로는 같은 말을 쓴다. 같은 대상을 두 이름으로 부르지 않는다.
- 제품·기능 이름은 화면 표기를 따른다. 화면이 영어면 영어 그대로 쓰고, 처음 나올 때 우리말 풀이를 붙인다.
- 외래어는 국립국어원 표기를 따른다(워크플로, 메시지, 콘텐츠).

## 5. 검사
- 저장소에 표기 검사 도구가 있으면(책의 집필 규칙이 정한 명령) 쓰기 전과 쓴 뒤에 실행한다. 고칠 곳이 0이어야 한다.
- 검사 도구가 잘못 잡은 곳은 원고를 고치지 말고 도구의 예외 목록에 더한다.
- 도구가 없는 규칙(어미의 일관성, 따옴표 종류)은 고친 문단을 다시 읽어 확인한다.
