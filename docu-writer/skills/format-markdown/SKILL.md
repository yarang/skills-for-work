# Markdown

이 스킬은 **Markdown 견본의 표기를 지키며 복사본을 고치는 법만** 담습니다. 무엇을 쓸지는 프로파일이, 디자인 규칙은 `design-review`가 정합니다.

## 분석 (②) — `profile_extract.py`

`template-analysis`의 `profile_extract.py`가 아래를 읽어 프로파일에 적습니다.

| 읽는 것 | 프로파일 |
|---|---|
| 제목 수준과 번호 붙임(`## 1. 개요`인지 `## 개요`인지) | `structure.numbering` |
| 목록 부호(`-`·`*`·`1.`)와 들여쓰기 칸 수 | `structure.numbering` |
| 표 정렬 표기(`:---`, `---:`), 강조 표기(`**`·`_`) | `design.table`, `voice` |
| 앞머리(YAML front matter) 키 | `fields` |
| 도표 표기(`![](*.svg)`인지 mermaid 코드 블록인지) | `design.diagram` |

`design.page`·`type`·`color`는 비워 둡니다. Markdown에는 서식 토큰이 없고, 보이는 모양은 뷰어가 정합니다.

## 작성 (⑤)

- **견본을 `.docu-writer/work/`에 복사한 뒤 복사본을 직접 편집합니다.** 별도 패치 스크립트는 없습니다.
- 제목은 `#` 수를 건너뛰지 않습니다(`##` 아래 바로 `####` 금지). 문서 제목 `#`은 하나입니다.
- 목록 부호와 들여쓰기 칸 수는 견본과 같게 씁니다. 한 목록 안에서 `-`와 `*`를 섞지 않습니다.
- 표: 머리행 다음 구분 줄을 반드시 두고, 숫자 열은 `---:`(오른쪽 정렬)로 씁니다. 칸 안 줄바꿈이 필요하면 표가 아니라 목록이 맞는지 다시 봅니다(`info-design`).
- 앞머리의 키 이름과 순서는 바꾸지 않습니다. 값만 바꿉니다.
- 도표는 `diagram-standards`대로 `.mmd`와 `.svg`를 개별 파일로 두고 `![설명](diagrams/<이름>.svg)`로 넣습니다. 견본이 mermaid 코드 블록을 직접 쓰면 견본을 따릅니다.
- 상대 링크·이미지 경로는 결과 파일 위치에서 열리는지 확인합니다. 복사본 위치가 다르면 경로를 고칩니다.
- 자리표시 `○○`는 `writing-principles`를 따릅니다. 줄 머리에 두지 않습니다(`- ○○`는 목록 항목 머리에 오므로 `- 담당: ○○`처럼 씁니다).

## 렌더 (⑥)

`doc-verify`의 `render.py`가 pandoc → DOCX → soffice → PDF → PNG로 미리보기를 만듭니다. 이 PNG는 **표·도표·위계가 깨지지 않았는지 보는 용도**입니다. pandoc 기본 서식으로 그려지므로 서체·쪽 나눔은 판정에 쓰지 않습니다.

## 검사 범위

- doc-verify는 `r1_tables`·`length`(쪽 수 기준)를 `skip`으로 냅니다. 분량은 글자 수 기준으로만 봅니다.
- R2(넘침)는 표 열 수로만 봅니다. 열이 7개를 넘으면 ⑦ design 리뷰어가 줄이거나 뒤집을지 판단합니다.
- R4(같은 수준 제목 같은 크기)는 `#` 수가 곧 크기이므로 「같은 뜻의 제목을 같은 `#` 수로」로 봅니다. R6(번호 양식 통일)은 제목 번호와 목록 부호로 봅니다.
