# 시각 디자인

이 스킬은 **토큰을 읽고 지키는 법만** 담습니다. 무엇을 표·목록으로 담을지는 `info-design`이, 규칙 판정(R1~R6)은 `design-review`가 정합니다.

## 원칙

- **견본 모드에서는 토큰을 읽고 지킵니다.** 새 서체·색·스타일·상자를 만들지 않습니다. 결과 파일이 쓰는 스타일은 프로파일 `design.styles_allowed` 안에서만 고릅니다.
- **서식은 직접 서식이 아니라 스타일로 입힙니다.** DOCX·PPTX에서 run마다 글꼴·크기를 직접 지정하지 않고, 견본 문단을 복제하거나 견본 스타일 이름을 씁니다. 직접 서식은 R5 검사에서 토큰 밖으로 잡힙니다.
- **토큰을 바꿔서 분량을 맞추지 않습니다.** 글자 크기·여백·줄 간격·자간 조정은 R5 위반입니다(`design-review`).

## 토큰 (프로파일 `design`)

| 토큰 | 담는 것 | 견본에서 읽는 곳 |
|---|---|---|
| `page` | 용지, 방향, 여백(mm, 위·아래·왼·오른) | DOCX 섹션 설정, PPTX 슬라이드 크기, HWPX `pagePr` |
| `type.body`·`type.hN` | 서체, 크기(pt), 굵기, 줄 간격(%) | 본문·제목 수준별 대표 문단의 스타일 → 없으면 실제 run 서식의 최빈값 |
| `color` | 글·강조·표 머리 바탕 색 | 테마 색과 실제 쓰인 색 가운데 2회 이상 쓰인 것 |
| `table` | 선(머리·외곽·안쪽), 머리행 굵기, 숫자 정렬, 합계 행 위치 | 견본의 첫 데이터 표 |
| `styles_allowed` | 쓸 수 있는 스타일·레이아웃 이름 | 견본에서 **실제로 쓰인** 스타일만 (정의만 된 스타일은 뺌) |
| `diagram` | 도표 색 팔레트, 글꼴 | `color.accent` + 회색 계열, `type.body`의 서체 |

- 값은 견본에서 실제로 쓰인 것의 **최빈값**을 대표로 잡습니다. 한 번만 쓰인 값은 예외로 보고 토큰에 넣지 않습니다.
- 같은 수준인데 견본 안에서 값이 둘 이상이면 프로파일에 둘 다 적지 말고 최빈값을 쓰고, 차이를 ④ 승인에서 보고합니다. 견본 자체가 R4·R5를 어긴 경우입니다.

## 표 서식 기본값

견본에 표가 없어 새로 넣어야 할 때만 씁니다. 견본 모드에서 견본에 없는 표를 넣는 것은 구조 변경이므로 먼저 보고합니다.

- 머리행: 굵게, `color.table_header_bg` 바탕, 가운데 정렬.
- 숫자: 오른쪽 정렬, 천 단위 쉼표, 단위는 머리행에 `(단위: 백만 원)`.
- 글: 왼쪽 정렬. 짧은 범주 값(구분·담당)은 가운데.
- 선: 외곽과 머리행 아래는 굵게, 안쪽은 가늘게. 세로선은 최소로.

## 색과 대비

- 글과 바탕의 명도 대비는 4.5:1 이상을 지킵니다(바탕색 칸 안 글 포함).
- 강조색은 한 문서에 하나(`color.accent`)를 씁니다. 빨강은 경고·감소에만 씁니다.
- 색만으로 뜻을 구별하지 않습니다. 굵기·기호·글을 함께 씁니다(흑백 인쇄 대비).

## 형식별 적용

토큰을 파일에 넣는 방법은 형식 스킬이 정합니다: `format-hwpx`(견본 문단 서식 복제), `format-docx`(스타일 이름), `format-pptx`(레이아웃·플레이스홀더), `format-markdown`(제목 수준만, 서식 토큰 없음).
