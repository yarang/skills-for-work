# 교육 덱 디자인

이 스킬은 **견본 없는 새 덱을 원고에서 시각화하는 법만** 담습니다. 견본 PPTX를 채우는 일은 `format-pptx`가, 규칙 판정(R1~R6)은 `design-review`가, 도표 작성은 `diagram-standards`가, 색 대비 기준은 `visual-design`이 정합니다.

## 적용 범위

- **견본이 없는 교육·발표 덱에만 씁니다.** 견본 PPTX가 있으면 `format-pptx`의 견본 복제 경로를 따릅니다. `newdoc-workflow` 카탈로그는 아직 PPTX를 받지 않으므로, 이 스킬은 `docu-writer:deck-design`으로 직접 불러 씁니다.
- **빈 레이아웃에 도형을 그립니다.** `format-pptx`의 「빈 레이아웃에서 새로 그리지 않습니다」는 지킬 견본이 있을 때의 규칙입니다.
- **역할별 글자 크기 범위가 이 덱의 토큰입니다.** 아래 「글자 크기 맞춤」의 범위 안에서 계산으로 크기를 고르는 것은 R5 위반이 아닙니다. 같은 슬라이드의 같은 역할은 한 크기로 맞춥니다(R4). 하한에서도 넘치면 글자를 더 줄이지 않고 `info-design`의 「줄이는 순서」로 글을 줄이거나 슬라이드를 나눕니다.
- **생성기는 `scripts/build_deck.py`입니다.** 아래 각 절의 수치는 이 스크립트가 그대로 따르는 규칙입니다. 프로젝트마다 다른 값은 코드를 고치지 말고 옵션과 config로 넘깁니다.
  - 실행: `uv run skills/deck-design/scripts/build_deck.py 원고.md -o 덱.pptx [--assets 자산폴더] [--config deck.yaml] [--font 서체] [--mono 코드서체] [--dump]`
  - 자산 폴더(기본은 원고가 있는 폴더)에 `icons/<이름>.png`, `illustrations/<이름>.png`, 그리고 원고의 `![..](diagrams/x.svg)`와 같은 자리의 `x.png`가 있어야 합니다. PNG는 `bash skills/deck-design/scripts/render_svgs.sh 자산폴더 [다이어그램 이름...]`가 자산 폴더의 SVG를 헤드리스 크롬으로 렌더해 만듭니다(크롬 경로는 `CHROME` 환경 변수). PNG가 없으면 생성기가 이 명령을 안내하고 멈춥니다.
  - config(YAML) 키: `png_remap`(SVG 이름 → 다른 PNG 이름), `badge_colors`(표 배지 글자 → 색), `colors`(테마 색 덮어쓰기), `skip_marker`(기본 「덱에 넣지 않음」), `subtitle_prefixes`(표지 부제로 쓸 인용 줄 머리, 기본 `대상:`·`기준:`), `spotlight_strip`(spotlight 단계 띠 기본값). 모르는 키는 오류입니다.
  - 첫 `##` 앞의 visual 주석은 문서 수준입니다. `{"hero": "그림이름", "strip": ["단계", ...]}`로 표지 그림과 spotlight 단계 띠를 정합니다. `##` 바로 아래 주석의 `{"icon": ..., "divider": false}`는 섹션 아이콘과 구분 슬라이드 생략입니다.
  - 종료 코드: 0 성공, 1 원고·주석·경계·자산 오류(메시지에 슬라이드 제목), 2 사용법 오류. `--dump`는 저장 뒤 슬라이드별 도형 이름(역할)·위치·크기·글자 크기를 찍습니다.
- 서체·색은 생성기 한 곳(테마 상수)에서만 정합니다. 슬라이드마다 상수 밖의 값을 쓰지 않습니다.

## 디자인 원칙

- **모든 내용 슬라이드에 시각 요소를 하나 이상 둡니다.** 글머리만 있는 슬라이드도 아이콘 하나는 붙입니다.
- **모티프는 하나만 씁니다. 색 원 안의 흰 아이콘입니다.** 강조 막대·색 띠는 쓰지 않습니다.
- **샌드위치 구성:** 표지·목차·구분 슬라이드는 어두운 바탕, 내용 슬라이드는 밝은 바탕입니다. 짧은 강조 슬라이드만 `dark`로 뒤집습니다.
- 색은 주색 하나(화면의 60~70%), 보조색 하나, 강조색 하나로 씁니다. 강조색은 배지·하이라이트 카드에만 씁니다.
- 그림·아이콘은 직접 그린 SVG만 씁니다. 웹에서 받은 이미지는 출처·저작권을 확인할 수 없고 폐쇄망에서 다시 만들 수 없습니다.
- 한 슬라이드에는 메시지 하나만 담습니다.

## 원고와 visual 주석

원고 마크다운 한 벌이 **단일 원본**입니다. 사람이 문서로 읽고, 생성기가 덱으로 바꿉니다. 덱을 고칠 때도 원고를 고치고 다시 생성합니다.

| 원고 | 덱 |
|---|---|
| `# 제목`, 아래 `> 대상:`·`> 기준:` | 표지 제목·부제 |
| `## 섹션` | 구분 슬라이드. 목차 한 줄 |
| `### 슬라이드` | 내용 슬라이드 |
| `- 글머리` / `- 예: …` | 글머리 / 말풍선 예시 카드 |
| `![설명](diagrams/x.svg)` · 표 | 그림 / 표 |
| `> 발표 노트: …` | 슬라이드 노트 |

`##`·`###` 바로 다음 줄에 `<!-- visual: {...} -->`(JSON 객체)를 두어 모양을 정합니다.

```markdown
## 3. 주요 기능
<!-- visual: {"icon": "tools"} -->

### 3.2 무엇을 할 수 있나
<!-- visual: {"layout": "cards", "cols": 2, "icons": ["chat", "doc", "search", "chart"], "highlight": [0], "chips": true} -->
- **질문하기**: 자료를 근거로 답을 받습니다
- 예: "지난달 회의 결정 사항 정리해 줘"
- 할 수 있는 일: 요약, 초안, 검색
```

- 주석이 JSON 객체가 아니면 생성기가 슬라이드 제목을 담은 오류를 내고 멈추게 합니다. 조용히 기본값으로 넘어가면 안 됩니다.
- 내용 슬라이드가 1장뿐인 섹션은 구분 슬라이드를 만들지 않습니다.
- 관리자용 부록처럼 덱에 넣지 않을 섹션은 원고에 「덱에 넣지 않음」을 적어 두고, 생성기가 그 표시를 보고 건너뛰게 만듭니다. 그런 섹션에도 비밀값은 적지 않습니다(`writing-principles`).

## 레이아웃 고르기

| layout | 이럴 때 | 옵션 |
|---|---|---|
| `icon-rows` | 항목 3~5개를 나열하고 숫자 하나를 강조 | `icons`, `stat {value, label, note}` |
| `spotlight` | 여러 단계 가운데 지금 위치를 짚음 | `icon`, `active` |
| `cards` | 비교하거나 묶을 것 2~6개 | `cols`, `icons`, `highlight`, `count_badge` |
| `steps` | 순서가 있는 절차 2~5단계 | (글머리 순서가 단계) |
| `image` | 도표·일러스트가 주인공 | 그림 비율에 따라 배치 자동 |
| `table` | 항목 × 속성 | `badge_col`(알약으로 그릴 열) |
| `timeline` | 기간·과정의 진행(표의 행마다 한 칸) | `icons` |
| `equation` | A + B = C 조합 | `terms [{icon, label}]`, `result` |
| `bullets` | 마지막 수단 | `icon`(글머리만 있어도 아이콘 하나는 붙임) |

공통 옵션: `badge`(제목 옆 꼬리표, 예: `"심화"`), `chips`(마지막 글머리를 알약 줄로), `dark`. layout을 적지 않으면 그림 → 표 → 글머리 순서로 고릅니다.

## 레이아웃 상수

16:9, 13.333 × 7.5in. 가로: 왼쪽 여백 0.6in, 내용 폭 12.13in(오른쪽 끝 12.73in). 세로: 내용 시작 1.4in(제목 아래), 내용 끝 6.95in. 카드 간격 0.25in.

**필요한 높이를 먼저 계산하고, 내용 묶음을 시작~끝 사이 세로 가운데에 둡니다.** 요소를 위에 붙이고 아래를 비워 두지 않습니다.

## 글자 크기 맞춤

| 역할 | 범위(pt) | | 역할 | 범위(pt) |
|---|---|---|---|---|
| 카드 머리글 | 14~20 (한 줄) | | 단계 글 | 15~24 |
| 카드 본문(머리글 있음) | 12~18 | | 타임라인 제목 | 13~18 (한 줄) |
| 카드 본문(머리글 없음) | 14~22 | | 타임라인 설명 | 12~16 |
| 그림 옆 글머리 | 13~18 | | 알약 라벨 · 개수 배지 · 단계 숫자 | 17 · 12 · 24 고정 |

큰 값에서 0.5pt씩 줄이며 **세 조건을 모두** 만족하는 첫 크기를 고릅니다.

1. **줄 수:** 추정 줄 수 × 크기 × 1.25 / 72 ≤ 상자 높이(in). 추정 줄 수는 문단마다 ⌈글 폭 ÷ (상자 폭 × 72)⌉을 더한 값이고, 글 폭(pt)은 글자마다 전각(한글) 1.0em, 그 밖 0.55em(본문 서체 평균)을 더해 셉니다.
2. **가장 긴 낱말:** 공백으로 나눈 낱말 중 가장 넓은 것(pt) ≤ 상자 폭(in) × 72 × 0.97. 이 검사에서만 전각이 아닌 글자를 0.56em으로 셉니다. 끊을 수 없는 긴 낱말은 대개 코드 서체(약 0.55em)로 찍힌 이름이라 조금 넉넉히 잡습니다. `parse_config_file,` 같은 코드 이름은 끊을 곳이 없어 PowerPoint가 낱말 중간에서 꺾습니다. 1번만으로는 이것을 못 잡습니다.
3. **통일:** 같은 슬라이드의 같은 역할(카드 머리글끼리, 카드 본문끼리)은 각자 맞춘 값의 **최솟값**으로 모두 맞춥니다. 카드마다 크기가 다르면 들쭉날쭉해 보입니다.

**한 줄이어야 하는 글**(머리글·타임라인 제목·라벨)은 자동 줄바꿈을 끄고, 추정 폭 × 1.1 ≤ 상자 폭이 되는 크기를 고릅니다. 1.1은 추정과 실제 렌더 사이의 여유입니다. 하한에서도 맞지 않으면 줄바꿈을 켜지 말고 글을 줄이거나 상자를 넓힙니다. 알약 라벨은 글상자 안쪽 여백을 0으로 두고 폭을 추정 폭 × 1.1 + 0.15in로 잡습니다.

## 배치 세부

- **머리글 없는 카드:** 아이콘을 카드 세로 가운데 왼쪽에 두고 본문은 그 오른쪽에 세로 가운데로 붙입니다. 본문 폭이 2.6in보다 좁으면 아이콘을 위, 본문을 아래 가운데에 둡니다. 이런 카드 묶음은 높이를 2.4in 안으로 묶습니다.
- **개수 배지:** 아이콘 원의 오른쪽 위에 겹쳐 답니다(알림 배지, 지름 0.34in). 카드 모서리에 두면 머리글 폭을 잡아먹습니다.
- **그림:** 원본 그림의 가로 ÷ 세로가 2.6 이상이면 위에 그림, 아래에 글을 둡니다. 2.6 미만이면 두 단으로 놓습니다. 왼쪽 64%에 그림, 0.35in 띄우고 오른쪽에 글머리·말풍선을 둡니다. 글이 없으면 그림을 내용 폭 전체로 씁니다.
- **단계:** 원 지름 0.8in, 숫자 24pt. [원 + 글] + 0.45in + 말풍선을 한 묶음으로 세로 가운데에 둡니다.
- **타임라인:** 열마다 설명 뒤에 흰 카드를 깝니다. 높이 = 가장 긴 설명의 줄 수 × 설명 크기 × 1.3 / 72 + 0.35in이고(1.3은 1.25보다 줄 사이를 넉넉히 둔 값, 0.35in는 위아래 여백), 모든 열이 같은 높이입니다.
- **알약 줄(chips):** 위 요소와 0.35in를 띄워 말풍선 꼬리가 닿지 않게 합니다.
- **경계 검사:** 생성기가 저장하기 전에 모든 도형이 슬라이드 안에 있는지 검사하게 만듭니다(허용 오차 0.01in). 벗어나면 슬라이드 번호·제목과 함께 실패해야 합니다.

## 도표·아이콘·서체

- 도표는 `diagram-standards`를 따릅니다. 덱에서는 슬라이드가 가로로 길다는 점을 고려합니다. 세로 흐름(`TD`)이 길어 그림이 작아지면 `LR`로 바꿉니다. 덱에는 mermaid-cli(`mmdc`)의 `-s 2`(2배 크기)로 렌더한 PNG를 넣습니다.
- 아이콘은 같은 viewBox·같은 선 두께의 단색 SVG로 직접 그리고, 흰색 PNG로 렌더해 색 원 위에 얹습니다. 파일 이름이 곧 visual 주석의 아이콘 이름입니다. SVG와 PNG를 나란히 두고 렌더 스크립트로 다시 만듭니다.
- 기본 서체는 맑은 고딕(Malgun Gothic), 코드는 Consolas입니다. 맑은 고딕은 Office 서체라서 Office가 없는 Mac의 Keynote·LibreOffice에서는 한글이 깨질 수 있습니다. 그런 환경용 덱은 서체 옵션을 Apple SD Gothic Neo로 바꿔 다시 생성합니다.

## 렌더 검수

1. 생성기를 실행합니다. 슬라이드 수와 경계 검사를 통과해야 합니다.
2. 슬라이드별 PNG를 만듭니다. `doc-verify`의 `render.py`(LibreOffice)는 구조와 넘침을 볼 때 씁니다. **줄 꺾임은 PowerPoint 렌더로 판정합니다.** LibreOffice는 맑은 고딕을 대체 글꼴로 그려 글자 폭이 다릅니다. macOS에서는 PowerPoint로 덱을 열어 PDF로 저장한 뒤 쪽별 PNG로 바꿉니다.
3. 전체를 몽타주 한 장으로 훑고, 의심 슬라이드만 원래 크기로 봅니다.
4. 이것들을 봅니다:
   - 낱말 중간 꺾임, 한 줄이어야 할 제목의 두 줄
   - 아이콘과 글의 겹침, 카드끼리 다른 글자 크기
   - 아래가 텅 빈 슬라이드, 말풍선 꼬리가 닿는 곳, 슬라이드 밖 도형

   지적에는 슬라이드 번호와 위치를 적습니다. R1~R6 판정은 `design-review`를 따릅니다.
5. **하위 에이전트의 「한 줄로 들어갔다」「확인했다」는 믿지 않습니다.** 메인 대화가 PNG를 직접 봅니다. 숫자가 필요하면 생성기를 `--dump`로 돌려 글상자별 위치·폭·글자 크기를 출력하게 하고, 그 출력을 보고에 붙이게 합니다.
6. 수정 지시는 **현상(렌더에서 본 사실, 슬라이드 번호) → 고칠 내용(수치)** 순서로 씁니다. 「보기 좋게」 같은 지시는 다시 같은 결함을 낳습니다.
